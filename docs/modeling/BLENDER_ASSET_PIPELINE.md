# Blender Asset Pipeline — Steel Front

## Project decisions

- User involvement: minimal. ChatGPT handles reference research, Blender source, modeling iterations, export, game integration and QA. Ask the user only at major visual acceptance gates.
- Target: Level 2 detailed real-time game asset.
- First vehicle: late-1944 ChKZ IS-2, displayed in-game as IS-2 Model 1944.
- Existing Three.js procedural model remains available as a fallback until the Blender asset passes visual and gameplay QA.
- Work on a dedicated branch; do not replace the live model or deploy until the new asset is validated.

## Source of truth and outputs

| File | Purpose |
|---|---|
| `docs/modeling/is2-model1944-reference-brief.md` | Research decisions, dimensions, variant caveats and citations |
| `tools/blender/build_is2_model.py` | Reproducible Blender Python source |
| `assets/blender/generated/is2-model1944.blend` | Native Blender scene, generated by CI |
| `public/models/is2-model1944.glb` | Runtime GLB asset for Vite/Three.js |
| GitHub Actions artifact `is2-blender-review` | Six-view renders, GLB and .blend for review |

The Python source is the reproducible authoring source. Do not hand-edit the generated GLB. Make geometry changes in the Blender script, regenerate, inspect, then commit the outputs.

## Coordinate and hierarchy contract

- Blender authoring units: metres; Z-up.
- Model front: positive Blender Y; vehicle left/right: negative/positive X.
- GLB export uses glTF Y-up conversion. Confirm the final orientation with the Three.js integration test before removing any runtime correction.
- Root object: `IS2_ROOT`.
- Independent game pivots: `HULL_ROOT`, `TURRET_ROOT`, `GUN_PIVOT`, `TRACK_L_ROOT`, `TRACK_R_ROOT`, and individual road-wheel pivots.
- Keep turret rotation about the turret-ring centre and gun elevation about the trunnion. Keep tracks and wheels separate from the hull.
- Use stable, descriptive object names. Do not join moving parts into a single mesh.

## Modeling sequence

1. Block the hull to real dimensions and lock its front/side/top silhouette.
2. Build the asymmetric cast turret and revised 1944 mantlet.
3. Add D-25T barrel, muzzle brake, coax port and sight port.
4. Build running gear: paired 550 mm wheels, idler, 14-tooth double-rim sprocket, return rollers and 86-link tracks.
5. Add four rear fuel tanks, hatches, cupola, ventilator, periscopes, headlights, exhausts, tools, tow cables and handrails.
6. Create PBR materials: painted rolled armor, cast steel, bare steel, rubber, dark optics and subtle wear.
7. Export GLB, render front/front-three-quarter/left/right/rear/top review views, and run structural checks.
8. Integrate behind the current procedural IS-2 fallback, then test turret traverse, gun elevation, recoil, collision, track/wheel motion and armor hit mapping.
9. Compare in-game views against the reference pack and optimize geometry/materials.
10. Only replace the live model after all checks pass and a final visual acceptance review.

## Quality/performance budget

- Target a clean, medium-detail silhouette with bevels and cast-steel surface breakup; avoid tiny geometry that is invisible in gameplay.
- Prefer reusable wheel/track-link meshes and instancing/merged static detail where appropriate.
- Keep animated pivots separate; static bolts, weld beads and small fittings can be combined by material.
- Use 2K textures only when they add visible value; favor compact 1K/2K packed maps and GLB material reuse.
- Target a sensible game asset budget (initial target 80k–150k triangles excluding optional high-detail extras; measure in CI and adjust from actual runtime profiling).
- Keep all optional date-specific equipment (DShK, special markings, smoke launchers) as variants rather than baking it into every Model 1944.

## Automated build

`.github/workflows/blender-is2.yml` installs Blender on a GitHub Actions runner, runs the authoring script in background mode, exports the native scene and GLB, creates six orthographic review renders, runs the Vite production build, and uploads the review package. The generated GLB and .blend are committed to this working branch only; they are not deployed from this branch.

## Acceptance gates

- Gate A — reference brief: source-backed variant and measurements.
- Gate B — Blender blockout: silhouette and proportions.
- Gate C — detailed asset: equipment and materials.
- Gate D — game integration: animation, collision, armor and performance.
- Gate E — live replacement: only after all automated tests and final visual comparison pass.

No user action is required for routine modeling. At Gate B and Gate E, provide a compact set of screenshots and request only a simple accept/revise decision.
